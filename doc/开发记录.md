# TJTUCore-8 开发记录

本文档详细记录TJUTCore-8的开发过程

## 一、移植单周期处理器开发环境

第一部分是移植单周期处理器的开发环境，经过讨论，决定在原有的RV32E单周期处理器基础上开发TJUTCore8，首先是移植开发环境。将ysyx-bench中的npc部分单独拿出来进行修改，其余部分不需要使用。

然后是删除设备文件和difftest

difftest主要在cpu-exec.c文件中被使用，当执行一条指令之后，需要调用difftest函数去进行对比，删除此行指令即可。
设备主要在初始化和执行过程中被使用，我们需要删除初始化阶段和内存阶段有关设备的函数。

删除设备文件和difftest之后，make run执行编译，出现报错，是因为没有修改Makefile文件中的路径，将路径改为TJUTCore之后，make run能够正常运行。

## 2. 删除所有的指令

目前的指令实现都是基于32位，因此为了更方便的实现8位处理器，我们首先删除所有的指令，先让cpu只能执行最简单的跳转指令，之后再添加各种指令。

我们只保留ebreak指令，这条指令标志着程序运行结束。

我们并不需要删除这些指令的识别部分，只需要删除它们的操作即可。指令识别删除完之后，运行make run，能够进入到简易调试器，但是运行bin文件时，产生报错：未识别的指令。说明我们已经成功删除了所有指令的识别，需要重新实现指令。

## 3. image文件的生成

为了确定我们处理器的实现方案，我们需要考虑可执行文件，也就是bin文件的内容。

目前我们使用的bin文件是来自于ysyx项目中编译出的方案，为了项目的完整度，我们需要从ysyx项目中将它的编译方案移植过来，同时学习riscv代码的编译过程。
